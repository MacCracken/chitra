# chitra — 2026-10-15 Security Audit (P(-1) sweep; all four formats, the sankoch boundary and the gate stack)

> **Status**: Sixth security audit of chitra, gating the 1.1.1 cut, and the
> first since the dependency boundary moved. The
> [2026-09-10 sweep](2026-09-10-audit.md) ran against cyrius 6.6.2 and the full
> stdlib sankoch 2.7.14. Since then the toolchain is 6.7.9 and sankoch is the
> **2.8.7 `zlib` profile**, resolved through `[deps.sankoch]` and composed into
> consumers transitively (closest-wins). None of that had been through an
> adversarial pass.
> **Date**: 2026-10-15 · **Version**: 1.1.1 (pre-tag; `chitra_version()` →
> 10101) · **Toolchain**: cyrius 6.7.9 · **sankoch**: 2.8.7, `zlib` profile.

## 1. Scope and method

chitra is a pure-Cyrius CPU raster decode **library**: untrusted encoded bytes
in, canonical RGBA8 out. The threat model is unchanged — a hostile image reaches
a public entry point and attempts an out-of-bounds access, an integer overflow
into an undersized allocation, an unterminated loop, a null dereference,
**silently wrong pixels**, or a **refusal that costs more than the file it
refuses** (the allocator never frees, so that cost is cumulative).

**Five lenses** ran in parallel, each over a disjoint slice:

1. **PNG and the sankoch boundary** — the chunk walk, inflate, unfilter, colour
   pass, and every error `zlib_decompress` can now return.
2. **JPEG, including error classification** — every refusal checked for whether
   it names the cause chitra actually declines.
3. **BMP and GIF.**
4. **Cross-cutting** — the router, the byte budget, refusal cost in all four
   formats, consumer composition after 1.1.0, the frozen surface, and every
   documented claim.
5. **The gate stack** — Makefile, scripts, CI and release workflows, the lock,
   and which guards a test can actually see.

Each lens had to back every finding with **evidence it ran** — bytes or a
generator, the command, observed against expected. Each lens's findings then
went to **one independent adversarial verifier** whose job was to refute them:
re-derive the control flow from the public entry point, re-run the reproduction
in its own scratch tree, and re-assess severity from scratch. The default was
refutation.

**65 findings were filed; 57 confirmed, 8 refuted.** Deduplicated across lenses,
the confirmed set is **about 40 distinct defects**: 5 HIGH, 10 MEDIUM, 42 LOW as
filed, **no CRITICAL**. Repairs were made in four file-disjoint areas, each by
an agent working in its own scratch copy, and merged here.

## 2. What the sweep did NOT find

⛔ **No memory-safety defect in shipped code.** Every out-of-bounds read or write
the sweep could construct needed a guard to be *removed* first. That is not a
clean bill: it is § 3.3, the largest class in this report — guards that exist,
work, and are held by no test.

Coverage that came back clean, each with its own measurement:

- **PNG** — every legal colour type × depth × interlace at widths 1–19 and
  heights 1–11 against chitra's own oracle; **384 ImageMagick-encoded files**
  byte-identical to `magick -depth 8 RGBA:-`; **23,000 bit-flipped or truncated
  zlib streams** with zero disagreement against CPython's `zlib`; the
  PCLMULQDQ CRC-32 path against slice-by-8 at every length 0–2,099 from
  misaligned offsets; 300 `alloc_reset()` + decode cycles with a filler written
  after every reset.
- **JPEG** — a **400-file random `cjpeg` sweep** (dimensions 1–129, every
  ΣHV ≤ 10 factor set, restart intervals, `-optimize`, `-dct float`) and 280
  multi-scan files against `djpeg -nosmooth`; a **1,500-case header-mutation
  differential** against djpeg whose 6 disagreements are all libjpeg's
  range-limit wraparound on extreme coefficients (chitra clamps; `djpeg -dct
  float` agrees with chitra); all 262 truncation points of a single-scan file
  report `seen_iend` 0.
- **BMP** — **504 real-encoder files** (ImageMagick BMP3/BMP2/V5 and ffmpeg),
  **1,026 crafted RLE/orientation/header files** and **618 BITFIELDS files** across
  17 mask layouts × five header sizes: the only differences are the documented
  sub-8-bit replication cells.
- **GIF** — **1,080 crafted files** (code sizes 2–8, interlaced heights 1–200,
  Clear-on-full and deferred-clear streams) and **648 real-encoder files** with
  zero disagreement against ImageMagick and ffmpeg.
- **Composition** — three consumer shapes on 6.7.9 each link exactly one sankoch
  bundle; two bundles in one program fail loudly (`global '_sankoch_mtx'
  redeclared`) rather than silently; fault-injecting each of the first 41
  sankoch allocations never crashes in any shape.
- **Frozen surface** — all 29 frozen signatures byte-identical to the 1.0.0
  bundle; `ChitraImage` offsets and size unchanged; every `_rgba8` wrapper agrees
  with its full decoder on all 53 non-square corpus files.
- **No regression of any 1.0.3 repair** (B-1 … B-7): each still has a test that
  fails when the repair is reverted.
- **Gate stack** — a moved sankoch tag, a failed clone and a drifted stdlib
  snapshot are each refused by `cyrius deps`; `cyrius test` fails on the parsed
  summary even when 256 failures wrap the exit byte to 0; `--poison` and
  `--bounds` give no false positives on the clean tree.

## 3. Confirmed findings and repairs

IDs are `C-n` for this sweep (B-n was 2026-09-10, A-n was 2026-08-24); the
sweep's own lens IDs are given in brackets so the working record can be traced.
Every repair below carries a regression test **checked to fail against the
pre-repair code** (or, for a test-gap finding, against the guard neutered), then
to pass — § 4 has the mutation results.

### 3.1 HIGH

#### C-1 · HIGH · A 5–13-byte `JFIF\0` APP0 counted as JFIF, overriding an Adobe RGB file's colour space [jpeg-1]

`_jpeg_parse_app0` set `saw_jfif` once the payload held five bytes reading
`JFIF\0`. libjpeg's `examine_app0` requires **14** (`APP0_DATA_LEN`). Because a
JFIF APP0 outranks the Adobe transform (CLAUDE.md JPEG rule 13), splicing a
9-byte APP0 after the SOI of a `cjpeg -rgb` file pushed its RGB samples through
the BT.601 inverse: **every colour byte wrong, no error**, and
`source_color_type` reporting 0x103 — telling the consumer the samples were
YCbCr. It is B-2 (1.0.3) in the opposite direction: B-2 added the APP0 check
without libjpeg's length condition.
**Repair**: JFIF requires a ≥ 14-byte payload. Tests: the 9-byte splice decodes
0x113 and byte-equal to the unspliced file (it was 0x103 with 1,149 colour bytes
changed); a full 14-byte JFIF still outranks Adobe, matching djpeg.

#### C-2 · HIGH · APP0/APP14 between scans re-decided the colour space after decoding [jpeg-2]

`_jpeg_resume_to_next_scan` parsed APP0 and APP14 into the frame's colour
evidence, and `_jpeg_build_image` read that evidence only after every scan had
decoded. libjpeg fixes the colour space at the first SOS; ImageMagick and ffmpeg
ignore later segments. A segment spliced between scans flipped a multi-scan
file's colour interpretation either way with no error — or, with transform 2,
refused a file all three references decode.
**Repair**: between scans, APP0/APP14 are length-skipped. Tests: an Adobe
transform 0 between scans of a YCbCr file and a JFIF APP0 between scans of an RGB
file each leave ctype and pixels unchanged (djpeg-identical); a transform-2
splice decodes.

#### C-3 · HIGH · Out-of-bounds guards in GIF, BMP and JPEG were held by no test [gif-gate-1, gate-1, bmp-gate-3]

Each of these guards is the only bound between attacker fields and a fixed-size
allocation, and each could be deleted with **all 13 suites and every fuzz harness
green** — the bump arena absorbs the overrun, so nothing crashes:

- **GIF**: the frame rect inside the logical screen (an out-of-bounds **write**
  ≥ 240 KB past a 24-byte canvas without it); the per-pixel palette index (both
  plain and interlaced paths); `code > next_code` in LZW; the dictionary
  ceiling `next_code < table_cap` — the ceiling 1.0.3's B-7 rewrote, which
  nothing pinned.
- **BMP**: the palette span against the input (out-of-bounds **read**); the RLE
  `y >= h` bound in **both** absolute and encoded mode — the verifier found that
  EOL and delta deliberately allow `y == h`, at which `_bmp_rle_put` writes up
  to `w` bytes **before** the index plane; the delta check at the jump; the
  absolute-mode `row_cap` half of B-6.
- **JPEG**: DHT Σcounts ≤ 256, DQT `Tq < 4`, AC coefficient index ≤ 63.
- **PNG**: the sub-byte palette index bound (reads past the input without it).

**Repair**: one rejection cell per guard, asserting the exact error code, each
shown to fail with only its guard neutered. No code changed.

### 3.2 MEDIUM

#### C-4 · MEDIUM · JPEG GATE 2 fired after every plane was allocated; padding bought B-3's 50 MB refusal back [jpeg-7, cc-1, gate-8]

1.0.3's B-3 added GATE 0 (`w·h·4 ≤ len·4096`) on the premise that GATE 2 "can
only run once every scan has been decoded". Every input to the summed entropy
span is byte-structural, though, so that premise was false — and GATE 0's
denominator is the file length, which **4,200 bytes of APP1 padding** raises:
a **16,658-byte file still spent B-3's exact 50,354,832 B** (and 4.8 s of CPU)
before being refused. Multi-scan files spent the earlier scans' planes the same
way.
**Repair**: `_jpeg_structural_espan` — an allocation-free pre-pass over every
scan header and entropy span — runs GATE 2 before any plane exists; the
post-decode GATE 2 stays as the exact backstop. Every padded fixture, single-
and multi-scan, now refuses at **22,160 B** (the table floor). A grayscale cell
in which GATE 0 and GATE 1 pass but GATE 2 refuses pins the summed-span bound
on its own. The accepted-file envelope is unchanged.

#### C-5 · MEDIUM · Every `cjpeg` file at quality ≤ 23 was refused as "bad quant table" [jpeg-3, cc-8]

At low quality `cjpeg` needs quant values above 255, so it writes **16-bit DQT
tables (Pq = 1) under SOF1**. libjpeg writes DQT before SOF, and chitra refused
`Pq ≠ 0` on sight — so a valid table was reported as malformed
(`CHITRA_ERR_JPEG_DQT`) before the classifier ever saw the mode it actually
declines. ADR 0004 and the roadmap both said SOF1 refuses as `JPEG_MODE`; for
every SOF1 file `cjpeg` emits, that was false.
**Repair**: a 16-bit table before any SOF is length-checked and consumed; the
frame's mode then decides (SOF1 → 22, SOF2 → 19, SOF9 → 20). A 16-bit table in a
SOF0 frame, `Pq > 1`, or a short body is still `JPEG_DQT`. The refusal also got
cheaper: `jpg_q5.jpg` goes from code 15 at 2,448 B to code 22 at 400 B.

#### C-6 · MEDIUM · Most validity guards had no test that fails without them [gate-4, png-4, png-5, gif-gate-2, gate-5, gate-6]

A whole-guard mutation sweep neutered **171** guards: **106 left every suite
green**. Several survivors are silent-wrong-output classes, not error-code
nits: PNG's short-inflate check (missing rows come back zero-filled), the IHDR's
own CRC, PLTE uniqueness (the second palette was silently used) and
PLTE-after-IDAT; GIF's GCE block size (A-6) and GCE revocation (A-5, opaque
pixels returned with alpha 0); JPEG's duplicate-component scan (whose
"load-bearing" comment was false).
⛔ **Erratum — the [2026-08-24 audit](2026-08-24-audit.md) says "every repair
carries a regression test verified to fail against the pre-repair code". For A-5
and A-6 that was false**: no commit has ever contained a test for either. The
dated report is left as written (it is a historical record); the correction is
recorded here, and both now have tests.
**Repair**: a cell per non-equivalent survivor in every format. Genuinely
equivalent survivors (JPEG `MAX_DIM` against a u16 field, the post-decode GATE 2
copy, Huffman `idx < 0`, the LZW chain-walk bounds) are documented as such in
the code so the next sweep does not re-flag them. Final mutation tallies are in
§ 4.

#### C-7 · MEDIUM · CI fuzzed without `--poison`, so it could see only crashes [gate-2]

`cyrius fuzz --poison` adds allocator redzones and exits 86 on an overwrite.
Neither CI nor `make fuzz` used it, so a small overflow into the next bump
allocation — exactly C-3's shape — passed. Four of C-3's mutants pass plain
fuzzing and fail poisoned.
**Repair**: `make fuzz` runs every `fuzz/*.fcyr` under `--poison`, and CI's fuzz
step *is* `make fuzz` (gate-16: the two used to walk different harness sets).
Proven: with GIF's frame-rect guard neutered, plain fuzzing passes and `make
fuzz` fails with `poison: redzone overwrite`.

#### C-8 · MEDIUM · Fuzz modes never reached the code their comments said they drive [gate-3]

Each harness mutated one fixture shape. PNG's scanline mode, documented as
driving "the five unfilter predictors, Adam7 and the colour pass", never
executed Adam7, the palette or sub-byte paths, colour type 4, 16-bit RGB or the
tRNS key; JPEG's "restart resync" mode used a fixture with no DRI; BMP never ran
RLE4; GIF never filled its dictionary. The 10.7 M-assertion figure overstated
what the fuzz gate protected.
**Repair**: fixtures for every structurally distinct path (PNG: ten shapes
including Adam7 RGB8/gray1/RGBA16, palette 8- and 2-bit with tRNS, gray-key,
ct4, 16-bit with key; JPEG: a DRI/RSTn fixture and a `cjpeg -rgb` fixture; BMP: an
RLE4 fixture; GIF: a stream that fills the table), each cross-checked byte-exact
against a reference decoder and self-checked by its harness. **No-op proof**: an
exit-on-entry probe in `_chitra_deinterlace`, `_jpeg_br_restart`, the RLE4 branch
and the LZW table-full branch makes each new harness fail; the 1.1.0 harnesses
passed with every probe in place. A latent bug went with it: the PNG harness's
LCG multiplier is a multiple of 5, so seed-based rotation would have visited 2
of 10 shapes.

#### C-9 · MEDIUM · The frozen numeric values of `ChitraErrCode` were pinned by nothing [gate-7]

`public-surface.md` puts the numeric values inside the 1.0 promise;
`check-surface.sh` compared only function names and every test compared codes
symbolically. Renumbering or swapping two codes shipped green.
**Repair**: `surface.tcyr` pins all 37 values literally and asserts 36–98 are
unnamed; `check-surface.sh` fails if an enum member has no name arm or no pin
row, and fails closed if it cannot read the enum.

## 4. Mutation results

- **PNG** — every new cell fails with its fix reverted or its guard set to
  `if (0)`; with all three code fixes reverted at once, `png.tcyr` fails exactly
  8 cells and `alloc_reset.tcyr` 1. Not pinnable: the IDAT accumulator cap
  (needs > 256 MB of input) and the colour pass's `entry_count <= 0` (equivalent:
  the index check refuses anyway).
- **JPEG** — a 54-mutant sweep over the repaired tree: every non-equivalent
  mutant killed, including every new 1.1.1 guard. Equivalent, and documented in
  code: the post-decode GATE 2 copy, DHT `remaining < 17`, SOF0 `MAX_DIM`
  against a u16, SOS `Ta ≥ 4`, Huffman `idx < 0` / `idx ≥ count` / `L > 16`, the
  driver's `sos_off == 0`.
- **BMP** — 34/34 mutants killed (one expected survivor:
  `stride·h > CHITRA_MAX_RAW_BYTES`, unreachable behind `CHITRA_MAX_PIXELS`).
- **GIF** — 30/30 killed (eight expected survivors: the outcome-identical span
  checks, the chain-walk bounds, the kept gather cap, and `cur < 0`).
- **Gates** — each changed gate was shown to fail on a constructed bad input and
  pass on the clean tree: poisoned fuzzing (frame-rect mutant), harness parity
  (an out-of-tree probe harness), every fuzz no-op probe, the budget mode
  (`_chitra_declared_rgba_bytes` neutered: 12,873–68,085 failures per harness),
  enum pins (a renumber and a swap), name checks (a deleted name arm), lint
  status (a broken bench file), strict deferrals (a probe comment), lock checks
  (seven lock mutations replayed through the real YAML), README fail-closed.

## 5. Behaviour a consumer can observe

Nothing frozen changed: 29 names, both record layouts and every error-code value
are as at 1.0.0. These outputs did change, every one toward the reference
decoders:

- **Now decode** (were refused): End-less GIFs whose padding fills a code; a
  truncated restart-interval JPEG (partial image, `seen_iend` 0); a grey or JFIF
  JPEG carrying an Adobe transform ≥ 2; a multi-scan file with APP14 transform 2
  between scans.
- **Now refused** (decoded before): a JPEG with a JPG/DHP/EXP or `0xF0–0xFD`
  segment; a scan whose components are out of frame order; an OS/2 2.x BMP with
  compression 3; a `bfOffBits = 0` BMP whose declared colour table runs past the
  end of the file.
- **Different pixels**: JPEG files carrying a short `JFIF` APP0 next to an Adobe
  transform, or APP0/APP14 between scans (now djpeg-identical); BMPs with
  `bfOffBits = 0` and a colour table (now correct); BMP channels wider than 8
  bits (now ImageMagick-exact).
- **`seen_iend` now 0** for out-of-sequence RSTn and for unconsumed entropy bytes
  before EOI. ⚠ This is **stricter than djpeg** in one case: djpeg is silent about
  up to ~6 trailing bytes (its bit buffer prefetches them). Checked against
  16 ffmpeg mjpeg files, 4 ImageMagick files and 133 `cjpeg` files: every one
  still reports 1.
- **Different error codes**: SOF1/SOF2/SOF9 with 16-bit tables (15 → 22/19/20);
  SOS before SOF (14 → 13); JPEG truncations (13/17 → 2); YCCK CMYK (4 → 23);
  sankoch OOM (5 → 6); second IHDR (4 → 3); OS/2 compression 3 at 1 bpp
  (24 → 26). ⚠ **kii maps chitra's codes**: a second IHDR now lands in kii as
  `PNG_ERR_HEADER` instead of `PNG_ERR_UNSUPPORTED`, and a sankoch OOM as
  `PNG_ERR_IDAT_TOO_LARGE` instead of `PNG_ERR_INFLATE`.
- **`chitra_err_name(CHITRA_ERR_SIGNATURE)`** reads "unrecognised image
  signature". Names were never frozen; match on codes.
- **Cheaper refusals** (§ 3.3, C-4): same codes, a fraction of the allocation.
  One refusal got *dearer*: a 3-component non-JFIF JPEG with an Adobe transform
  > 1 is now judged at the first SOS, after its tables, so it costs 22,160 B
  instead of 400 B — inside the B-3 table floor.

## 6. Refuted, and deliberately not changed

**Refuted by the verifiers** (8):

- *PNG bad filter byte / bad palette index refused after the next buffer*
  [png-6] — both depend on decompressed data, so no header can decide them, and
  neither refusal spends more than the file's valid twin.
- *Lying-IHDR mismatches surface as `INFLATE`* [png-7] — the lying-IHDR check is
  the bomb-ratio cap (`DIMENSIONS`); the exact-size check is a second line,
  documented as `INFLATE / DIMENSIONS`.
- *Non-letter chunk types classified by bit 5* [png-9] — PNG § 13.5 tells a
  decoder to do exactly that.
- *No real 12-bit JPEG gets `JPEG_PRECISION`* [jpeg-9] — documented in the
  roadmap's *Out of scope*.
- *An RLE BMP missing end-of-bitmap is refused* [bmp-rle-noeob] — deliberate:
  BMP has no incomplete-but-decoded state.
- *An empty GIF LZW chain reports `DIMENSIONS`* [gif-empty-lzw] — a frame with
  zero data bytes is the dimensions-vs-data case that code names.
- *BMP RLE pre-gate can be padded past* [cc-4] — the documented, strictly weaker
  pre-gate (B-4); the exact cap still precedes the allocation it protects.
- *check-surface truncates mixed-case names* [gate-12] — lint fails any
  mixed-case `fn` name first, so the stack as a whole blocks it.

**Decided, not repaired**:

- **The GIF ratio stays in pixels.** Making the code match the docs (×4 stricter)
  would refuse legitimately maximal-compression solid GIFs; the docs were wrong,
  so the docs moved (C-35).
- **The sankoch floor is documented, not enforced** (C-26). No public sankoch
  symbol carries a version, and a link-time floor would couple chitra to sankoch
  internals and break every consumer on an older toolchain.
- **cc-13 — 125 unprefixed bundle globals** (`IMAGE_*_OFFSET`, `HT_SIZE`, …)
  that a consumer's same-named global silently overrides. Confirmed, LOW, and
  **deferred to its own 1.1.x patch**: renaming 125 names is too much churn to
  ship alongside forty other repairs, and the cross-check found no collision in
  any consumer today.
- **Fuzz memory** was not a finding but surfaced during repair: the JPEG harness
  peaked at **16.3 GB RSS** (GIF 8.7 GB) because the arena never frees between
  cases — against a 16 GB CI runner. Every harness now runs in **heap epochs**:
  every 1,024 cases it sweeps the poison redzones, calls `alloc_reset()` and drops
  its memoized fixtures. Peaks: JPEG **54 MB**, GIF 207 MB, PNG 6.5 MB, BMP 4.4 MB;
  assertion counts identical; runtime +10 %.

## 7. Status after this audit

All 57 confirmed findings are repaired, documented as decided, or (cc-13)
scheduled. **3,949 assertions across 13 suites, 0 failures** (3,086 at 1.1.0).
Fuzz, all four harnesses under `--poison` (`make fuzz`): **11,185,700
assertions, 0 failures** — PNG 3,017,096, JPEG 3,447,819, BMP 3,305,017, GIF
1,415,768 (10,732,113 at 1.1.0, unpoisoned and reaching far less of the code).
The 53-file reference corpus decodes byte-identically to 1.1.0 except
`jpg_q5.jpg`, whose refusal code is now `JPEG_MODE` (C-5).

Open, carried to the roadmap: cc-13 (prefix the bundle's globals and gate it),
and a CI consumer-shape leg that would catch C-26's floor if a consumer
toolchain drops below it.
